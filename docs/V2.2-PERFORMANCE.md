# APEX Vision AI v2.2 — Performance

## Objective

v2.2 improves rendering speed, resource efficiency, cache reuse, and frontend responsiveness without changing the visualization product scope.

## Implemented baseline

- Render stage timing: scene, tile load, render, write, total.
- Runtime cache counters: hits, misses, errors.
- Bounded in-process LRU tile texture cache.
- Configurable tile texture memory bound.
- Configurable tile cache item limit.
- OpenCV `INTER_AREA` downscaling for oversized source tile textures.
- Deterministic render smoke/performance regression test.
- Existing scene cache remains the primary AI-analysis reuse mechanism.

## Runtime configuration

- `APEX_TILE_TEXTURE_MAX_DIM` — maximum source texture dimension before resize; default `1024`.
- `APEX_TILE_CACHE_MAX_ITEMS` — maximum in-process tile textures retained; default `32`; `0` disables the tile cache.
- `APEX_RENDER_MAX_DIM` — existing render-size configuration; minimum `256`.

## Operational metrics

`GET /api/render/metrics` reports aggregate render timing, completion/failure counts, cache behavior, and average stage durations. These values are process-local and are intended for operational baselining in v2.2.

## Baseline procedure

1. Run the full CI suite.
2. Execute the deterministic render performance test.
3. Run representative room/tile renders with the same provider and settings.
4. Record cold render and cached render timings from `/api/render/metrics`.
5. Compare future changes against the baseline before tightening thresholds.

## Performance guardrail

The automated render smoke test uses a deliberately generous five-second ceiling on the GitHub runner. It is a regression guard, not a production SLA. Production targets should be established from representative hardware and workloads before enforcing stricter CI limits.
